## 1. 目的と背景

### 背景
- いまは毎週次の3つを手元で作っている。
  - 全銘柄の一括分析(土曜3:00に自動実行)
  - 来週の買い候補(J-Quants 側と TechnicalAnalysis 側の2系統)
  - グランビルの買い②③のウォッチリスト
- 結果は Markdown・CSV・PNG に分かれて `output/` の下に散らばっており、Mac の前でないと見られない。
- チャートは matplotlib の静止画なので、期間を変えたり線を足したりするには作り直しが要る。

### 目的
1. 週次の分析結果・市場の状況・個別銘柄のチャートを、**1か所で、スマホからも**見られるようにする。
2. 既存の分析の約束(§4.0)を崩さずに表示する。見やすくするために、点数を付けたり、手法を合成したりはしない。
3. 最終確認は TradingView で行う今の流れは変えない。ポータルは「候補を絞るまで」を楽にする道具とする。

### やらないこと
- 売買の判断を自動化すること、推奨を出すこと
- 既存の分析ロジックの作り直し(分析は既存のプロジェクトで行い、ポータルは表示に徹する)

#### F1-6 の詳細(お金の流れ: マクロ→ミクロ)

画面案: https://claude.ai/artifact/18sGE53YeMFoL4ddonf2sr の下の段「変更案 ①〜③」(PC。数値はダミー。上の段の「現行案」は旧案)

##### 考え方
- **最重要の問い: 今どこにお金が集まっているか。**
  - 相場全体にお金が入ると、どの区分・業種も売買代金は増える。
  - 金額だけを見ていると、プライムからスタンダードへ資金が移っても気づけない。
- そこで、2段目以降は金額ではなく**シェア**(全体の売買代金に占める割合)で比べる。
  - シェアは取り合いなので、どこかが増えれば別のどこかが減る。
  - 資金の移動が数字に表れる。
- どの階層でも、同じ順で見る。
  1. 量(いくら入っているか)
  2. 配分(どこにあるか)
  3. 変化(どこへ動いたか)

##### 階層と画面の移り方
| 段 | 画面 | 次の段へ |
|---|---|---|
| (⓪) | 世界(**先送り**) | 作るときは①の上に置く |
| ① | 日本市場 | 配分の帯グラフか「市場区分ごとに見る」を押す |
| ② | 市場区分(プライム・スタンダード・グロース) | 区分の「業種を見る」を押す |
| ③ | 業種(33業種) | 業種を選ぶ(④へ) |
| ④ | 銘柄 | **未決**(§9) |

- どの画面にも、上部に階層ナビ(①日本市場 › ②市場区分 › ③業種 › ④銘柄)を置き、どの段にも戻れるようにする。

##### 期間と「直近」の決め方(全画面共通)
- **期間**
  - 13週・26週・52週の3つから選ぶ。
  - 選んだ期間は、階層を移っても引き継ぐ。
  - 期間ボタンは、どの画面でも階層ナビの右に置く。
  - 既定は52週(**仮置き**)。
- **「直近」の幅は、期間に合わせて変える**(2026-09-24 決定)。
  - 13週 → 直近2週
  - 26週 → 直近4週
  - 52週 → 直近8週
- **比べ方は、ならした平均どうしで比べる**(2026-09-24 決定)。1週だけの値は使わない。
  - シェアの変化(pt) = 直近の平均シェア − 選んだ期間全体の平均シェア
  - 期間平均比(%) = 直近の平均シェア ÷ 選んだ期間全体の平均シェア − 1
- 見出しや列名は、選んだ期間に合わせて文言を変える(例: 「選んだ期間(26週)の中で、直近4週にお金が集まっている区分」)。

##### ⓪ 世界(**先送り**。2026-09-25)
> 初版では作らない。データ元の確定・週の区切り・出来高の代理など課題が多いため。以下は検討した内容の記録で、再開するときの出発点とする。

- **目的**
  - 日本株の外も含めて、世界のお金がどの資産に向かっているかを最初に見る。
  - そのうえで①日本市場へ掘り下げる。
- 作るときはトップ画面にする想定(2026-09-25 に一度決めた)。
- **対象の資産**(8つ。2026-09-25 決定)

  | 資産 | 価格として見るもの | 出来高として見るもの |
  |---|---|---|
  | 米国株 | S&P 500 | S&P 500 連動 ETF(SPY など)の売買代金(代理) |
  | 米国債券 | 米国10年国債の利回り | 米国債 ETF(TLT・IEF など)の売買代金(代理) |
  | 日本株 | TOPIX(J-Quants) | 全銘柄の売買代金の合計(F1-6 ①と同じ) |
  | 日本債券 | 日本10年国債の利回り | 長期国債先物の出来高、または公社債の店頭売買高(**要確認**) |
  | 中国株 | 上海総合指数 または CSI 300(**未決**) | 指数の売買代金。取れなければ中国株 ETF の売買代金(代理) |
  | 為替(ドル円) | ドル円レート | 為替には取引所がなく、市場全体の出来高は取れない。円の先物か円 ETF の出来高で代理する(**要確認**) |
  | 金 | 金価格 | 金 ETF(GLD など)の売買代金(代理) |
  | ビットコイン | ビットコイン価格(円建て または ドル建て。**未決**) | 取引所の売買代金 |

  - 「代理」は、その資産そのものの出来高が取れないので、連動する ETF や先物の出来高で代わりに示すという意味。画面にも「代理」と表示する。
- **見せ方**
  - 期間(13週・26週・52週)と「直近」の幅は、F1-6 の共通の決まりに従う。
  - 選んだ期間は①以降へ引き継ぐ。
  - 資産ごとに、価格の推移と出来高の推移を上下に並べた小さなチャートを並べる。
  - どの資産も週足にする。
  - 資産ごとに次の2つを表示する。
    - **価格の変化**: 選んだ期間の騰落率。債券は利回りの変化(bp)で示し、「利回りが上がる = 債券価格は下がる」と書き添える。
    - **出来高の期間平均比**: 直近の平均出来高 ÷ 選んだ期間全体の平均出来高 − 1。
  - 冒頭に、出来高の期間平均比が大きい順の要約を置く。例: 「出来高が期間平均より増えている: 金 +35%、ビットコイン +20%…」
- **資産どうしの比べ方**
  - 資産によって出来高の単位や規模がまったく違う。そのため、日本株の画面のように「全体の中のシェア」では比べない。
  - どの資産も、自分自身の期間平均と比べた増減(期間平均比)で比べる。
- **週の区切り**
  - 市場ごとに取引時間と休日が違う。そのため、各市場の「その週の最終取引日の終値」を、その週の値とする。
  - 米国市場の金曜の終値が出そろうのは、日本時間の土曜の朝。したがって、世界の段が週として確定するのは土曜の朝になる。
    - 日本の17:00ルール(§5.2)とずれるので、**未決**(§9)。
  - ビットコインは休みなく取引されるので、週の区切りの時刻を決める必要がある(**未決**)。
- **通貨**
  - 価格は各市場の通貨のまま騰落率で示す(**仮置き**)。
  - **未決**: 円に換算した騰落率も並べるか。
- 資産を選ぶと、その資産の詳細に進む。
  - 日本株を選んだときは①へ。
  - ほかの資産の詳細は**未決**(§9)。

##### ① 日本市場
- 画面名は「日本市場」(2026-09-25 変更)。日本株の売買代金に加えて、国債利回り・ドル円・原油(F1-7)も載せるため、「日本株全体」では内容と合わない。
- 数値
  - 直近の週の売買代金(週合計)
  - 13週平均との比
  - 選んだ期間の中での順位(パーセンタイル)
- チャート: 選んだ期間の分だけを、同じ時間軸で上下に並べる。
  - 上の段: TOPIX(週の終値)
  - 下の段: 売買代金(週合計)の棒と、13週移動平均(**仮置き**)
- **配分の帯グラフ**
  - 直近週の市場区分ごとのシェアを、100%の横帯で示す。
  - 区分ごとに、シェアの変化(pt)を矢印(▲/▼)で添える。
  - 帯を押すと②へ進む。

##### ② 市場区分
- 冒頭に要約を置く。例: 「シェアが増えたのはスタンダード +1.2pt、減ったのはプライム・グロース」
- 区分ごとに小さなチャートを横に並べる。
  - シェアの推移(線)
  - 選んだ期間の平均(点線)
  - 直近の範囲の網かけ
  - その区分の売買代金(薄い棒)
- **縦軸は区分ごとに変える。**
  - プライムは約8割を占めるので、同じ縦軸だとスタンダードやグロースの動きが見えない。
  - 軸が違うことを、画面に書き添える。
- 表の列
  - 直近週のシェア
  - 直近の平均シェア
  - 期間の平均シェア
  - シェアの変化(pt。0を中心に左右に伸びる棒を添える)
  - 売買代金の「直近平均 ÷ 期間平均」
- 2022年4月の市場再編より前の週は、旧区分(東証1部・2部・マザーズ・JASDAQ)で集計する。
  - **未決**: 新区分と、どう並べてつなぐか。

##### ③ 業種(33業種)
- 対象は「全市場 / プライム / スタンダード / グロース」で切り替える。
  - ②から来たときは、選んだ区分を最初から選んでおく。
- 冒頭に要約を置く。集まっている業種と抜けている業種を、上位3つずつ示す。
- **ヒートマップ**(業種 × 週。選んだ期間の分)
  - 色の値は「その週のシェア ÷ 期間の平均シェア − 1」。
  - 期間平均より多いほど濃い赤、少ないほど濃い青にする。±30%以上は同じ色にする(**仮置き**)。
- 業種の並び順は、直近の期間平均比が大きい順にする。
- 「集まっている業種」と「抜けている業種」の境目に区切り線を引く。
- 業種ごとに次の列を並べる。
  - 直近週のシェア
  - 直近の期間平均比(0を中心に左右に伸びる棒)
- 業種ごとの比べ方は、シェアの差(pt)ではなく**期間平均比(%)**にする(**仮置き**)。
  - 業種によってシェアの大きさがまったく違うため。
  - 例: 電気機器は約2割、パルプ・紙は1%未満。
- 業種は、その週の時点の銘柄一覧(`/equities/master` の S33)で振り分ける。後から業種が変わった銘柄を、過去にさかのぼって振り替えない。

##### 集計の仕方
- 全銘柄の株価四本値の売買代金(`Va`、円)を、週ごと・区分ごと・業種ごとに合計する。
  - TOPIX の四本値には出来高がないので使わない。
  - `/equities/bars/daily` は日付を指定すれば全銘柄を一括で取れる。
- **表示するのは売買代金だけ。** 株数の出来高は出さない(2026-09-24 決定)。
- **週足だけを表示する。** 日足は出さない(2026-09-24 決定)。
  - 週は、その週の最終営業日の17:00以降に確定してから表示する。未確定の週は出さない。
- 営業日が5日未満の週には印を付ける。祝日や半日立会(取引カレンダーの HolDiv=2)がある週のことで、週合計が小さく出るため。
  - シェアは同じ週の中での割合なので、営業日数の影響は受けにくい。

#### F1-8 の詳細(市場全体の EPS・PER)
- **置き場所**: ①日本市場の画面と、②市場区分の画面(区分ごと)(2026-09-25 決定)。
- **期間**: F1-6 の期間ボタン(13週・26週・52週)に連動させる。週足で表示する。
- **データ**: J-Quants だけで作れる(外部のデータ元は要らない)。
  - 利益: 決算短信(`/fins/summary`)の当期純利益の**会社予想だけ**を使う(`FNP`。実績は使わない。2026-09-25 決定)。
  - 時価総額: 株価四本値(`/equities/bars/daily`)の `MktCap`。
- **計算の仕方**
  - **市場全体の PER** = 対象銘柄の時価総額の合計 ÷ 対象銘柄の当期純利益(会社予想)の合計。
    - 1銘柄ずつの PER の平均ではなく、合計どうしで割る。大きい会社ほど強く効き、指数の PER と同じ考え方になる。
  - **市場全体の EPS** = TOPIX ÷ 市場全体の PER。
    - 「TOPIX 1ポイントあたりの利益」の意味。この値が伸びていれば、市場全体の利益が伸びている。
  - 対象銘柄は、F1-6 と同じ集計対象(ETF・REIT などを除く)のうち、次をどちらも満たす銘柄とする。
    - 会社予想を出している。
    - 当期純利益の会社予想が**黒字**(0より大きい)。**赤字予想の会社は除く**(2026-09-25 決定)。
  - 外した銘柄は、分子(時価総額)からも分母(利益)からも外す。
  - 黒字か赤字かは、その週の時点で最新の会社予想で判定する。予想が赤字に変わった週から外れ、黒字に戻った週から入る。
- **会社予想の切り替え**
  - 本決算の発表で、会社予想は翌期のものに切り替わる。各銘柄について、その週の時点で最新の会社予想を使う。
  - 翌期の予想は、本決算の短信では `NxFNP` に入っている。どちらを使うかは、開示の種類で決める。
- **17:00ルールを守る**
  - 基準日の17:00までに開示された決算短信だけを使う(既存の `jquants/availability.py`、`ta/fins.py` と同じ考え方)。
  - 過去の週の PER も、その週の時点で分かっていた予想で計算する。あとから出た予想で過去を塗り替えない。
- **見せ方**
  - ①では市場全体、②では市場区分(プライム・スタンダード・グロース)ごとに出す。
    - ②の区分ごとの EPS は、TOPIX ではなく区分の時価総額で割るため意味が変わる。②では **PER と、利益の合計の変化(%)** を出す(**仮置き**)。
  - 直近の値と、選んだ期間の中での変化を表示する。
    - PER: 倍と変化(倍)
    - EPS: 値と変化(%)
  - チャート: EPS と PER の推移を並べる。
  - **株価の変化の分解**: TOPIX = EPS × PER なので、選んだ期間の TOPIX の騰落率を「EPS の変化(業績)」と「PER の変化(期待・評価)」に分けて示す。
    - 例: 「TOPIX +8% = 利益 +3% + 評価 +5%」
    - 上昇が業績によるものか、期待によるものかを見るため。
- **注意**
  - 赤字予想の会社を除くので、PER は赤字の会社を含めた場合より低く出る。
  - 赤字と黒字の入れ替わりで対象銘柄が変わると、PER や EPS が動く。画面に「対象銘柄数」と「除いた赤字予想の銘柄数」を出す。
  - 予想の修正や、本決算で予想が翌期に切り替わる時期(5月・11月など)には、EPS が段差のように動く。
  - 実装したら、JPX が公表している「規模別・業種別 PER・PBR」(月次)と水準を突き合わせて確かめる(**要確認**: 公表の形式と算出方法)。

#### F1-9 の詳細(主体別売買動向)
- **目的**: F1-6 で「どこにお金が集まっているか」を見た。ここでは、そのお金を「誰が」動かしているかを見る。
- **データ**: J-Quants の投資部門別情報(`/equities/investor-types`)。

  - 市場全体の週次の集計で、銘柄ごとのデータはない。
  - 項目: 主体ごとの売り・買い・合計・差引(買い越し額)。
- **主体**(表示するもの。2026-09-25 決定)
  - 海外投資家
  - 個人
  - 投資信託
  - 事業法人(自社株買いが含まれる)
  - 信託銀行(年金の売買が多く含まれる)
  - 証券会社の自己売買
  - 生保・損保、都銀・地銀等、その他金融機関、その他法人は「その他」にまとめる。
- **置き場所**(2026-09-25 決定)

  - ②市場区分: プライム・スタンダード・グロースごと。データに市場の区分(`Section`)があるため。
- **期間**: F1-6 の期間ボタン(13週・26週・52週)に連動させる。

  - 選んだ期間の累計の差引を、主体ごとに並べる。例: 「海外投資家 +1.2兆円、個人 −0.8兆円」
  - F1-6 と同じく、「直近の平均」と「期間の平均」を比べて、買い越しが増えている主体を要約する(**仮置き**)。
- **公表のずれ**

  - 17:00ルールに合わせて、公表日の17:00より前には、その週の分を使わない。
- **注意**
  - 2022年4月の市場再編の前後で、市場の区分の名前が変わる。
    - 例: 再編前は東証1部・2部・マザーズ・JASDAQ など、再編後はプライム・スタンダード・グロース。
    - 東証全体の合計は、再編の前後でつながるように集計する(**要確認**: 区分の値の一覧)。
  - 差引は、現物株の売買だけの数字。先物は含まない。

### 5.2 データの扱いの約束
- **17:00ルール。** 「その日の17:00時点で取得できたデータ」だけを、その日の値として扱う。
  - 判定には、データの日付(`Date`)ではなく、取得できるようになる日時を使う。
- **株価は分割・併合を調整した値を使う。**
  - J-Quants の調整後の値は「取得した時点での調整」なので、取得した日が違うデータを並べるとずれる。
  - 既存の `swing/panel.py` と同じく、調整前の値に AdjFactor の累積積を掛けて、自分で揃える。
- **銘柄コードは文字列で扱う。** 英字を含むものがある(`287A` は応答では `287A0`)。
- **市場区分は、2022年4月の市場再編の前後で読み替える。**
- **対象外の銘柄**: ETF・REIT(`0109`)、TOKYO PRO MARKET(`0105`)。
- **履歴は約10年分。** 開始日は日々ずれていく(既存の実装は `HISTORY_START = "2016-09-23"`)。

| 一括分析・買い候補 | 土曜の一括分析(3:00開始、約40分〜1時間)が終わったあと | Mac の launchd に同期の処理を足す |
| J-Quants の買い候補 | `weekly_picks.py` を実行したあと | 同上。**未決**: 自動で実行するかどうか |

### 5.5 J-Quants 以外のデータ(⓪世界の段。**先送り**)

**方針**
- できるだけ無料のデータ元を使う。必要なら一部を有料にすることも検討する(2026-09-25 決定)。
- 下の表の候補は、**どれも利用規約・取得方法・更新時刻をまだ確認していない**。実装の前に確認する(§9)。
- とくに次の2点に注意する。
  - 公式の API でない取得(Web サイトからの取り込み)は、止まったり、規約で禁じられていたりすることがある。
  - 指数(S&P 500 など)の価格は、指数を作っている会社の許諾条件がかかることがある。

| 資産 | 価格の候補 | 出来高の候補 | 無料か |
|---|---|---|---|
| 米国株 | S&P 500(米国セントルイス連銀 FRED など) | SPY などの ETF の日足(Stooq などの日足データ) | 無料の見込み |
| 米国債券 | 米国10年国債利回り(FRED) | TLT・IEF などの ETF の日足 | 無料の見込み |

  - 外部の API キーも Mac の外に出さない。
  - 無料の API は、回数の制限を守って取得する。

## 6. システム構成案

### 前提
- 分析は Mac の上で動いている。ポータルでは作り直さない。
  - launchd による定期実行
  - anaconda の Python
  - パネル 約2GB、キャッシュ 約1GB
- ポータルはクラウドに置き、スマホからも見られるようにする。

### 案A: Mac から送る(推奨)
```
[Mac] J-Quants / TechnicalAnalysis(今のまま)
   └─ 追加: 出力を JSON などに変換し、クラウドへ送る処理(一括分析のあとと、平日17:00以降)
        ↓
[クラウド] ストレージ / DB
        ↓
[クラウド] ポータル(読むだけ。ログイン必須)
```
- 長所
  - 分析の結果と完全に一致する。
  - J-Quants の API キーを Mac の外に出さずに済む。
  - クラウド側の処理が軽く、費用も安い。
- 短所
  - Mac が止まっていると、データが更新されない。
- 送るデータの量(**仮置き**)
  - 週次の分析: 数MB
  - 株価: 表示用に銘柄×週足/日足の約10年分

### 案B: クラウドで J-Quants を直接呼ぶ(比較用)
- 長所
  - Mac が止まっていても、株価は最新になる。
- 短所
  - API キーをクラウドに置く必要がある。
  - 分析の結果は結局 Mac から送る必要があるので、案A との二本立てになる。
  - レート制限(120回/分)をクラウド側でも管理する必要がある。

### 技術スタック(未決。候補)
| 層 | 候補 |
|---|---|
| フロントエンド | Next.js / SvelteKit / Streamlit(Python のまま作れる) |
| チャート | TradingView Lightweight Charts(対数目盛り、ローソク足、記号を描ける) / ECharts |
| 保存先 | Supabase(Postgres + Storage + 認証) / Cloudflare R2 + D1 / 静的な JSON |
| ホスティング | Vercel / Cloudflare Pages / Streamlit Community Cloud |
| 同期 | Mac 側の Python スクリプト(launchd から呼ぶ) |

## 7. 非機能要件
| 項目 | 要件 |
|---|---|
| 認証 | 本人だけがログインできる。ログインしていない人には何も表示しない。検索エンジンに載せない(`noindex`) |
| 秘密情報 | J-Quants の API キーはリポジトリに入れない(`.env` は `.gitignore` 済み)。ブラウザに渡さない |
| 利用規約 | J-Quants のデータは個人利用の範囲で使い、第三者に見せない。**要確認**: クラウドに置いて本人だけが見る使い方が、規約上問題ないか。§5.5 の外部データも、データ元ごとに同じことを確認する |
| 表示速度 | 画面の表示は3秒以内(**仮置き**)。判定表は約1,000行を、ページ送りなしで絞り込めること |
| スマホ | 横幅375px で、横スクロールせずに主要な情報を読める。判定表は、列を絞った表示に切り替えられる |
| 費用 | 無料枠の範囲が基本。月額の上限は**未決** |
| API の流量 | 既存の実装と同じく100回/分に抑え、429 のときは1分以上待つ。財務系は60回/分 |
| 可用性 | 個人用なので、止まっても翌日に直せばよい。データ更新の失敗はわかるようにする(最終更新時刻の表示、失敗の記録) |
| 保守 | 分析のロジックはポータルに複製しない。形(§5.3)が変わったら、同期の処理だけを直す |

## 8. 制約と前提
- J-Quants のスタンダードプランの範囲で作る(§5.1)。
- どの手法も較正していない。J-Quants の買い候補も、検証で銘柄選定の優位性は確認できていない。
  - 確認期間の超過リターンは +0.18%(t値 0.33)。
  - ポータルはこれを前提に、情報を**見る**道具として作る。
- 取引は買いだけ。時間軸は週足が中心(判断は金曜の引け後、注文は翌週の営業日だけ)。

  - 株価100円以上
  - 履歴52週以上
- 既存の2つのフォルダは git で管理していない。

## 10. 用語集
| 用語 | 意味 |
|---|---|
| 基準日 | 分析の時点。原則、直近で週足が確定した週の最終営業日(通常は金曜、祝日の週は木曜)。その日の17:00時点で使えたデータだけを使う |
| 17:00ルール | データの日付ではなく「取得できるようになった日時」で、使えるかどうかを決める約束 |
| 判定 | 手法ごとの「買い / 中立 / 売り / 判定不能」 |
| 局面 | 手法ごとの状態の名前(例: グランビルの買い②、バンドウォーク(上)) |
| 仮置き | 典拠の資料に数値がなく、とりあえず決めた閾値 |
| 指値 / 損切り / 目標 | 買いの値段 / 逆指値の売り / 利食いの指値売り |
| R:R | リワード÷リスク。(目標−指値)÷(指値−損切り) |
| 約定確率 | 翌週の有効期間中に、指値まで下がって買える確率(推定値) |
| 期待リターン | 各結果の確率 × リターンの合計。「注文1件あたり」は、買えない場合の0を含む |
| 代理(出来高) | その資産そのものの出来高が取れないときに、連動する ETF や先物の出来高で代わりに示すこと |
| シェア | ある区分・業種の売買代金が、同じ週の全体の売買代金に占める割合 |
| EPS・PER(市場全体) | PER = 時価総額の合計 ÷ 当期純利益の合計(会社予想。赤字予想の会社を除く)。EPS = TOPIX ÷ PER。F1-8 |
| 期間平均比 | 直近の平均シェア ÷ 選んだ期間全体の平均シェア − 1。業種どうしを比べるときに使う |
| 支持線の重なり | 押しの比率・移動平均線・旧高値などの支持線の候補が、同じ値段帯にいくつ重なっているか |
