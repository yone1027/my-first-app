## 1. 概要

### 1.1 目的
次の2つを、1か所で、PC とスマホから見られるようにする。スプリント1では、Mac の上で動かし、同じ家のネットワーク(Wi-Fi)のスマホからも見る。
- 日本市場の状況(お金の流れ、指標、業績と評価、主体別売買動向)
- 週次の分析結果(一括分析の判定表、来週の買い注文の候補、買い候補)

個別銘柄のチャートはポータルでは作らない。TradingView で見る。

### 1.2 利用者と利用環境
| 項目 | 内容 |
|---|---|
| 利用者 | 本人1人 |
| 動かす場所 | 本人の Mac。Mac にログインしたときに自動で起動する(スプリント1) |
| 見る端末 | その Mac のブラウザ(横幅 1280〜1440px を主に想定)と、同じ家のネットワークにつないだスマホ(横幅 375px 以上) |
| 開き方 | Mac では `http://localhost:<ポート>`、スマホでは `http://<Mac の名前>.local:<ポート>`(**仮置き**) |
| ログイン | スプリント1では置かない。合言葉も置かない。家の外(インターネット)からは開けない |
| ブラウザ | 最新の Chrome・Safari(**仮置き**) |
| 言語 | 日本語のみ |
| 時刻 | 日本時間(JST)で表示する |

### 1.3 範囲
| 区分 | 機能 |
|---|---|
| 作る(スプリント1) | 市場概況(F1)、週次の分析結果(F2)、共通機能(F0。ログインを除く)、スマホでの表示 |
| クラウド版で足す | ログイン(G-00)、家の外からの閲覧 |
| 作らない | 銘柄詳細(旧 F3)、⓪世界の概況(先送り)、発注、複数ユーザー、リアルタイム株価、スマホ専用アプリ |

### 3.1 画面をまたいで引き継ぐもの
| 引き継ぐもの | 範囲 | 方法(**仮置き**) |

## 4. 共通仕様

### 4.1 画面の枠(全画面共通)
| 領域 | 内容 |
|---|---|
| ヘッダー左 | サイト名「株価ポータル」。押すと G-11 |
| ヘッダー中央 | 上部メニュー「市場概況」「週次の分析結果」。今いる方を太字と下線で示す |
| ヘッダー右 | 銘柄検索(§4.5)、データの時点(§4.3) |
| 本文の先頭 | 画面ごとの見出し。市場概況は階層ナビ、週次の分析結果は基準日とタブ |
| 注意書き | 週次の分析結果の画面では、本文の先頭に必ず出す(§4.6) |

### 4.2 スマホでの表示(横幅 768px 未満。スプリント1から。切り替える横幅は**仮置き**)
- ヘッダーの上部メニューと銘柄検索は、メニューボタン(≡)の中にしまう。
- 横に並んだカード・チャートは、縦1列に並べ直す。
- 横スクロールはさせない。ただし G-21 の判定表と G-13 のヒートマップは、表の中だけ横に動かせる。
- G-21 の判定表は、局面の文字を出さず、判定のラベルだけにする。
- G-11・G-12 の主体別の凡例(主体の一覧)は、グラフの下に置く。
- ボタンなど押せるものは、高さ 44px 以上にする。

### 4.3 データの時点の表示
- ヘッダー右に、次の2行を常に出す。
  - 1行目: 「データ: YYYY-MM-DD の週まで」(市場概況)、または「基準日 YYYY-MM-DD」(週次)
  - 2行目: 「最終更新 YYYY-MM-DD HH:MM」
- 最終更新が予定より遅れているときは、2行目を注意の色にし、「更新が遅れています」と添える。
  - 予定: どの画面も、土曜の週次の後続の処理(§7)が終わる土曜 12:00 までに、その週の分が入る(**仮置き**)。土曜 12:00 を過ぎても前の週のままなら「遅れ」とする。

### 4.4 期間の選び方(市場概況 G-11〜G-13)
| 項目 | 仕様 |
|---|---|
| 選択肢 | 13週 / 26週 / 52週 |
| 既定 | 52週(**仮置き**) |
| 置き場所 | 階層ナビの右。見出し「期間(次の画面にも引き継ぐ)」 |
| 「直近」の幅 | 13週 → 2週、26週 → 4週、52週 → 8週 |
| 範囲 | 選んだ期間の週足だけを表示する。最新の確定した週が右端 |
| 文言 | 「直近◯週」「期間(◯週)」の◯は、選んだ期間に合わせて変える |

### 4.5 銘柄の検索
| 項目 | 仕様 |
|---|---|
| 入力 | コード(4〜5文字。英字を含むことがある。例: `287A`)、または社名の一部 |
| 候補 | 入力のたびに、最大10件を下に出す。表示は「コード 社名(市場)」 |
| 選んだとき | G-21 を開き、その銘柄の行を表示する。行の中に「TradingView で開く」を出す(**仮置き**) |
| 一括分析の対象外の銘柄 | 「この銘柄は一括分析の対象外です(時価総額 1,000億円未満など)」と出し、「TradingView で開く」だけを出す |
| 見つからない | 「該当する銘柄がありません」 |

次の文を出す。文面は全画面で同じにする。
> どの手法も較正していないため、売買判断として使えるものではない。確率は推定値で、保証ではない。検証では銘柄選定の優位性は確認できていない。

| 画面 | 出し方 |
|---|---|
| G-21〜G-23 | 本文の先頭に枠で出す。画面ごとの一言を後ろに足す(各画面の仕様を参照) |

### 4.7 TradingView へのリンク
- 銘柄名と「TradingView で開く」は、TradingView のその銘柄のチャートを新しいタブで開く。
- URL は `https://jp.tradingview.com/chart/?symbol=TSE%3A<コード>`(**仮置き**)。
  - コードは4文字の表記にする(J-Quants の `287A0` は `287A`)。

### 4.8 色
| 用途 | 色 | 使う場所 |
|---|---|---|
| 買い / 増えた / 買い越し | 赤系 `#B5452B` | 判定のラベル、▲、増加の棒、ヒートマップの多い側 |
| 売り / 減った / 売り越し | 青系 `#2F6690` | 判定のラベル、▼、減少の棒、ヒートマップの少ない側 |
| 中立 | 灰色 | 判定のラベル |
| 判定不能 | 白地に灰色の文字 | 判定のラベル |
| 食い違い | 紫系 | フラッグ/ペナントの判定のラベル |
| 市場区分 | プライム `#2E4057`、スタンダード `#3E8E7E`、グロース `#9A5B8F` | G-11 の帯グラフ、G-12 のチャート |
| 主体 | 海外投資家・個人・投資信託・事業法人・信託銀行・証券会社の自己売買に1色ずつ | 主体別売買動向 |

- 色だけで区別しない。▲▼の記号、「+」「−」の符号、文字のラベルを必ず付ける。
- 要件 F0-5 の「ローソク足の色」は、ローソク足を描く画面がなくなったため使わない。

### 4.9 数値と日付の書式
| 種類 | 書式 | 例 |
|---|---|---|
| 金額(兆円) | 小数1桁。主体別の金額は小数2桁 | 33.7兆円、+1.52兆円 |
| 金額(億円) | 整数・3桁区切り | 250,544 |
| 株価・指数 | 3桁区切り。株価は整数、TOPIX は整数、平均値や損切り価格は小数1桁まで | 2,498、4,085、2,581.0 |
| 割合(%) | 小数1桁。増減には必ず符号を付ける | 7.2%、+18% |
| ポイント(pt) | 小数1桁、符号付き | ▲ +1.2pt |
| 倍 | 小数2桁。PER は小数1桁 | 1.11倍、15.3倍 |
| 利回りの変化 | bp の整数、符号付き | +17bp |
| パーセンタイル | 整数(0〜100) | 71 |
| 日付 | `YYYY-MM-DD`。週は `MM/DD〜MM/DD` | 2026-09-18、09/14〜09/18 |
| 曜日 | 基準日には付ける | 2026-09-18(金) |

- 値がないときは「—」を出す。0 と区別する。

### 4.10 データが足りないときの表示
| 状況 | 表示 |
|---|---|
| 週がまだ確定していない | その週は描かない |
| 公表がまだの週(主体別売買動向など) | 網かけで「未公表」と示す |
| データ元の更新が遅れている(F1-7 の指標など) | 最新の週を描かず、「◯月◯日の週までの値」と添える(**仮置き**。要件 F1-7 の要確認) |
| 期間の途中から始まるデータ | ある週だけ描く。計算は、ある週だけで行う |
| 読み込み中 | 各カードの中に、灰色の仮の形を出す |
| 読み込みに失敗 | カードの中に「データを読み込めませんでした」と「再読み込み」のボタンを出す。ほかのカードはそのまま表示する |

## 5. 画面ごとの仕様

### 5.0 G-00 ログイン(クラウド版から。スプリント1では作らない)
スプリント1では、この画面はなく、どの URL もそのまま開ける。以下はクラウド版の仕様として残す。

| 項目 | 仕様 |
|---|---|
| 入力 | 本人のアカウントでのログイン(方式は**未決**。例: メールのリンク、外部アカウント) |
| 成功 | G-11 を開く。ログインする前に開こうとした画面があれば、その画面を開く |
| 失敗 | 「ログインできませんでした」と出す。理由の詳しい説明は出さない |
| ログインの有効期間 | 30日(**仮置き**)。切れたら G-00 に戻す |
| ログインしていない | どの URL を開いても G-00 に移す。データは何も返さない |
| 検索エンジン | すべてのページを `noindex` にする |

### 5.1 G-11 市場概況 ① 日本市場

上から、量 → 配分 → 誰が動かしたか → 業績と評価 → 周りの指標、の順に並べる。

#### (1) 見出し
- 階層ナビ: 「① 日本市場 › ② 市場区分 › ③ 業種 › ④ 銘柄(次の段階)」。今いる段を黒丸で示す。②③は押すと移る。④は押せない。
- 期間ボタン(§4.4)。
- 見出し「お金の流れ: 日本市場」。

#### (2) 売買代金の数値(3つのカード)
| カード | 値 | 補足の文字 |
|---|---|---|
| 直近の週の売買代金 | 最新の確定した週の、全銘柄の売買代金の合計(兆円) | 「(MM/DD〜MM/DD)」「週合計」 |
| 13週平均との比 | 直近の週 ÷ 直近13週の平均(倍) | 「13週平均 ◯◯ 兆円」 |
| 期間の中での位置 | 直近の週の売買代金が、選んだ期間の中で何パーセンタイルか | 「100 = 期間内で最大」 |

#### (3) TOPIX と売買代金のチャート
| 項目 | 仕様 |
|---|---|
| 上の段 | TOPIX の週の終値の線と、13週線・26週線・52週線(F1-1)。移動平均線は凡例を押して表示を切り替えられる。既定はすべて表示(**仮置き**)。期間より前の週も使って計算する |
| 下の段 | 売買代金の週合計の棒と、13週移動平均の線 |
| 横軸 | 選んだ期間の週。月の変わり目に「◯月」、年の変わり目に「YYYY/M」 |
| 印 | 営業日が5日未満の週の下に ▲ を付ける |
| 操作 | 週にカーソルを合わせる(スマホは押す)と、その週の期間・TOPIX・13週線・26週線・52週線・売買代金の週合計・13週平均との比を出す |

#### (4) どこに配分されているか
| 項目 | 仕様 |
|---|---|
| 帯グラフ | 直近週の市場区分ごとのシェアを100%の横帯で示す。幅が狭い区分は、帯の中に名前を書かない |
| 区分ごとの数値 | 区分名、直近週のシェア、シェアの変化(▲▼と pt) |
| 説明の文 | 「矢印は、直近◯週の平均シェア − 選んだ期間(◯週)の平均シェア(ポイント)」 |
| 操作 | 帯か「市場区分ごとに見る」を押すと G-12 |

#### (5) 誰がお金を動かしたか(主体別売買動向・東証全体)
| 項目 | 仕様 |
|---|---|
| 見出しの説明 | 「最新は MM/DD〜MM/DD の週の分(MM/DD 公表)」を必ず出す |
| 要約 | 「直近◯週で、買い越しが期間平均より増えている主体: ◯◯、◯◯　減っている主体: ◯◯」(§6.7) |
| グラフ | 週ごとに、選んだ主体の買い越し額を0より上、売り越し額を0より下に積み上げる棒。TOPIX の線を重ねる |
| 目盛り | TOPIX は左、買い越し額は右(兆円)。買い越し額の目盛りは、選んだ主体に合わせて変える |
| 未公表の週 | 右端の週を網かけにし、「未公表」と書く |
| 主体の一覧(凡例を兼ねる) | 主体ごとに、色の四角、主体名、補足(事業法人「自社株買いを含む」、信託銀行「年金の売買を多く含む」)、期間の買い越し額の合計、「1週あたり: 直近◯週 ±x.xx / 期間 ±x.xx」 |
| 操作: 主体を押す | その主体の表示と非表示が切り替わる。複数選べる。外した主体は、四角を中抜きにし、行を薄く表示する |
| 操作: すべて選ぶ / すべて外す | 6つとも表示 / 6つとも外す |
| 表示数 | 「◯ / 6 を表示」 |
| 既定 | 6つとも表示 |
| すべて外したとき | 棒を描かず、TOPIX の線だけを描く |
| 「市場区分ごとに見る」 | 押すと G-12 |

#### (6) 業績と評価(市場全体の EPS・PER)
| 項目 | 仕様 |
|---|---|
| 説明の文 | 「PER = 時価総額の合計 ÷ 当期純利益(会社予想)の合計。赤字予想の会社は除く。EPS = TOPIX ÷ PER」 |
| カード: PER | 直近の週の値(倍)と、期間の変化(倍) |
| カード: EPS | 直近の週の値と、期間の変化(%) |

## 6. 表示する値の計算方法

どの値も、基準日の17:00時点で使えたデータだけで計算する(要件 R3・§5.2)。

### 6.1 週と期間
- 週: 月曜〜金曜の営業日。週の値は、その週の最終営業日の17:00以降に確定する。
- 期間: 最新の確定した週を含む、直近 N 週(N = 13・26・52)。
- 直近: 期間の最後の R 週(R = 2・4・8)。

### 6.2 売買代金
- 週合計 = その週の全営業日・全対象銘柄の売買代金(`Va`)の合計。
- 対象銘柄: ETF・REIT・TOKYO PRO MARKET を除く(含めるかは**未決**。要件 §9-8)。
- 13週移動平均 = その週までの13週の週合計の平均。
- 期間の中での位置 = 期間の各週の週合計のうち、直近の週以下の週の割合 × 100(整数に丸める)。

### 6.3 シェアとその変化
- シェア(%) = 区分(または業種)の週合計 ÷ 全体の週合計 × 100。
- シェアの変化(pt) = 直近 R 週の平均シェア − 期間 N 週の平均シェア。
- 期間平均比(%) = (直近 R 週の平均シェア ÷ 期間 N 週の平均シェア − 1)× 100。
- ヒートマップの値(%) = (その週のシェア ÷ 期間 N 週の平均シェア − 1)× 100。
- 業種の対象を区分にしたときは、分母を「その区分の全体の週合計」にする。

### 6.4 区分と業種の振り分け
- その週の時点の上場銘柄一覧(`/equities/master`)の市場区分と S33 業種で振り分ける。
- 後から変わった区分や業種で、過去の週を振り替えない。

### 6.5 営業日が5日未満の週
- 取引カレンダーで、その週の営業日(半日立会を含む)が5日未満の週。半日立会(HolDiv=2)がある週も含める。

### 6.6 指標(F1-7)
- 利回りの変化(bp) = (期間の最後の週の値 − 期間の最初の週の値)× 100。
- ドル円・原油の変化(%) = (期間の最後の週の値 ÷ 期間の最初の週の値 − 1)× 100。

### 6.7 主体別売買動向(F1-9)
- 週の買い越し額 = その週の主体の差引(買い − 売り)。
- 期間の合計 = 期間のうち公表済みの週の買い越し額の合計。
- 1週あたり: 直近 R 週 = 公表済みの最後の R 週の平均。期間 = 公表済みの週の平均。
- 要約の「増えている主体」 = (直近 R 週の平均 − 期間の平均)が大きい上位2つ。「減っている主体」 = 最も小さい1つ(**仮置き**)。
- ①は東証全体、②は区分ごと。2022年4月より前の区分の読み替えは**要確認**(要件 F1-9)。

### 6.8 EPS・PER(F1-8)
- 対象: 会社予想の当期純利益が黒字の銘柄。判定は、その週の時点で最新の会社予想で行う。
- 市場全体の PER = 対象銘柄の時価総額の合計 ÷ 対象銘柄の当期純利益(会社予想)の合計。
- 市場全体の EPS = TOPIX ÷ 市場全体の PER。
- PER の変化(倍) = 期間の最後の週の PER − 最初の週の PER。
- EPS の変化(%) = (最後の週の EPS ÷ 最初の週の EPS − 1)× 100。
- 値動きの分解: TOPIX の騰落率・EPS の変化率・PER の変化率を並べる。3つは掛け算の関係((1+TOPIX)=(1+EPS)×(1+PER))なので、足し算では一致しない。画面にもそう書く。
- ②の区分ごと: PER は区分の対象銘柄で同じ計算。「利益の合計」の変化(%) = (最後の週の利益の合計 ÷ 最初の週の利益の合計 − 1)× 100。

### 6.9 買い判定の数(F2-1)
- 5つの手法(グランビル・決算ブレイクアウト・フラッグ/ペナント・ボリンジャーバンド・MACD)のうち、判定が「買い」の数。
- 絞り込みの「5 / 4 / 3」は、それぞれ「その数以上」。

### 6.10 株数の目安(F2-2)
- リスク上限 = 投資資金 × 5%。
- 1株あたりのリスク = 買いの指値 − 損切り。
- 株数 = リスク上限 ÷ 1株あたりのリスク(小数は切り捨て)。
- 単元での株数 = 株数を100株単位に切り捨て。

## 7. データが更新されるタイミングと読み元

### 7.1 更新のタイミング
データは週に1回、土曜に更新される(要件 §6.1「週次の後続の処理」)。

```
土曜 3:00  一括分析(既存)            → G-21 のデータ
土曜 3:00〜 週次の後続の処理(一括分析の終わりを待って動く)
            1. candidates.py        → G-23 のデータ
            2. weekly_picks.py      → G-22 のデータ
            3. 市場概況の集計         → G-11〜G-13 のデータ
```

| 画面・欄 | 更新のタイミング | 画面の変わり方 |
|---|---|---|
| G-11〜G-13 の売買代金・シェア・TOPIX | 土曜(市場概況の集計の後) | 前の週(金曜まで)が右端に加わる |
| G-11・G-12 の EPS・PER | 同上 | 同上 |
| G-11・G-12 の主体別売買動向 | 同上。公表済みの週の分まで | 「未公表」だった週が埋まる(株価より1週遅れる) |
| G-11 の指標(F1-7) | 同上。公表済みの週の分まで | 最新の週が加わる。公表が遅れた週は、次の週に埋まる |
| G-21 | 土曜(一括分析の後) | 基準日に新しい週が加わり、「最新」になる |
| G-22 | 土曜(`weekly_picks.py` の後) | 同上 |
| G-23 | 土曜(`candidates.py` の後) | 同上 |

- 画面を開いたまま更新されても、自動では書き換えない。開き直すか、再読み込みしたときに新しいデータを出す(**仮置き**)。
- 一括分析と後続の処理は順に進むので、土曜の朝の途中には、G-21 だけ新しい週があり、G-22・G-23 はまだ前の週までということがある。そのときは、G-22・G-23 のタブで新しい基準日を選ぶと「この週のデータはありません」と出す(§5.4 (1))。

### 7.2 データの読み元
ポータルは次の場所を読むだけで、書き換えない(要件 §6.1)。場所は設定ファイルに書く。

| 画面 | 読む場所 |
|---|---|
| G-21 | `/Users/yone/TechnicalAnalysis/output/screen/<基準日>/`(`verdicts.csv`・`results.jsonl`・`report.md`・`universe.csv`) |
| G-22 | `/Users/yone/J-Quants/output/selection/picks_<基準日>.csv`・`.md`、`plans_<基準日>.csv` |
| G-23 | `/Users/yone/TechnicalAnalysis/output/candidates/<基準日>/candidates.csv` |
| G-11〜G-13 | `/Users/yone/StockPortal/data/`(市場概況の集計の結果) |

- G-21 の基準日の一覧には、`verdicts.csv` と `report.md` がそろったフォルダだけを出す(一括分析の途中の週は出さない)。
- フォルダ名が日付だけでないもの(例: `20260911_trial`)は読まない。
- `results.jsonl` に同じ銘柄が複数行あるときは、最後の行を使う。

## 8. エラーと例外

| 状況 | 表示 |
|---|---|
| ログインしていない(クラウド版) | G-00 に移す |
| ログインの期限切れ(クラウド版) | G-00 に移し、「もう一度ログインしてください」 |
| 家の外から開こうとした(スプリント1) | 接続を受け付けない(画面は出ない) |
| 存在しない URL | G-90 に「ページが見つかりません」と、G-11 へのリンク |
| 存在しない基準日 | 最新の基準日で開き、「指定した基準日のデータはありません」と上に出す |
| 週次の後続の処理が失敗した・止まっている | §4.3 の「更新が遅れています」。失敗した手順の画面(例: G-22)に「この週のデータはありません」 |
| ポータルが動いていない(Mac がスリープ中など) | ブラウザの接続エラーになる(ポータルからは何も出せない) |
| ポータルの中の障害 | G-90 に「表示できません。時間をおいて開き直してください」 |

## 9. 外から見える非機能の仕様

| 項目 | 仕様 |
|---|---|
